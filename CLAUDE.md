## Design Context

### Users
- Primary users are individual SPOs managing one or more Cardano stake pools.
- Typical usage context is personal operations on macOS for machine management, deployment, upgrades, KES lifecycle handling, and runtime monitoring.
- Core job to be done: complete critical pool operations without terminal-level complexity while keeping control and traceability.

### Brand Personality
- Personality keywords: 专业、克制、极简.
- Emotional goals: confidence, calm, and operational clarity during both routine tasks and incidents.
- Tone should stay factual, precise, and low-noise.

### Aesthetic Direction
- Visual direction: minimal and Apple-style desktop product feel (reference direction: mainstream Apple apps, including Codex-like clarity).
- Theme policy: light mode only for now.
- Color usage: align with Cardano brand palette as the source of truth; keep accents restrained and prioritize readability over decoration.
- Anti-direction: avoid cluttered dashboards, excessive chroma, ornamental effects, and visually loud status treatments.

### Design Principles
1. Task-first clarity: prioritize current operation, state, and next action over decoration.
2. Progressive disclosure: show simple defaults first; reveal advanced controls only when needed.
3. Risk-aware interaction: any potentially disruptive operation should be explicit, confirmable, and reversible where possible.
4. Status integrity: surface real runtime state and errors directly, with concise diagnostics and no ambiguous success states.
5. Accessibility baseline: meet WCAG 2.1 AA and support reduced motion preferences.
