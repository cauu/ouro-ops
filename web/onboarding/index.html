Describe your pool

      
Save a pool-spec.yaml on the agent's machine. Put each SSH private key at ~/.ouro/credentials/<name> for its creds://<name> reference. Keep pool-specific notes in a POOL-NOTES.md next to it.

    

    
spec_version: 1
pool:
  network: mainnet
  network_magic: 764824073
  genesis_hashes:
    shelley: "1a3be38bcbb7911969283716ad7aa550250226b76a61fc51cc9a9a35d9276d81"
topology_mode: p2p
machines:
  - id: bp1
    role: bp
    ssh: { host: <bp-ip>, port: 22, user: "<ssh-user>", key_ref: "creds://bp1" }
  - id: relay1
    role: relay
    public_endpoint: { host: <relay-ip>, port: 3001 }
    ssh: { host: <relay-ip>, port: 22, user: "<ssh-user>", key_ref: "creds://relay1" }

Ask in plain language

      
Reads run freely. Anything that changes a node is shown to you first and runs only after you approve.

    

    
    
      
  • Health — sync, peers, disk, logs, and whether the BP can actually produce blocks (valid opcert, not just a running container).
    • 
      
  • Changes — restart, config and topology edits with backups, image upgrades relay-first.
    • 
      
  • KES rotation — new KES key on the BP, an offline signing bundle for your cold machine, verified install. Requires the ouro-ops CLI on the agent's machine.
    • 
    

    
Cold keys never leave your offline machine, and no skill asks for them.
